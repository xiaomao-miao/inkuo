# inkuo AI 提示词中文审计

本目录是对仓库中 AI 提示词体系的中文翻译与行为审计。它只解释当前实现，不会替代或修改运行时提示词。

## 阅读顺序

1. [架构与装配流程](01-architecture.md)：先理解一轮请求究竟叠加了哪些内容。
2. [核心模式提示词](02-core-modes.md)：Agent、Ask、Plan、Edit 四种模式的中文翻译。
3. [子代理提示词](03-subagents.md)：9 个专家角色的完整中文翻译。
4. [工具规范](04-tool-specs.md)：`get_tool_help` 按需注入的 7 份已注册规格，以及 2 份未注册动画规格的翻译。
5. [动态片段与补全提示](05-overlays-and-completion.md)：功能开关、运行时状态、代码/DOCX 补全。
6. [前端生成的用户提示](06-frontend-prompts.md)：快捷操作、右键 AI、Cmd+K、计划再执行等。
7. [问题与改进建议](07-findings-and-recommendations.md)：为什么模型可能显得迟钝，以及建议的调整顺序。
8. [全量索引](08-inventory.md)：按来源和运行状态核对是否遗漏。
9. [关于 shell / 脚本运行权限的澄清](09-shell-and-scripting.md)：解释“Agent 没有执行权限却仍然写脚本”的真实成因与补救方式。
10. [执行策略备忘](10-execution-policy.md)：先禁止写脚本，待工具集齐后再分级开放——本轮共识与未来沙盒前置条件。

## 范围

纳入：

- 所有运行时 system prompt、子代理 persona、功能叠加片段。
- 所有按需工具规范及关键工具 schema 描述。
- Rust 中硬编码的动态提示、补全提示与测试请求提示。
- 前端自动构造并发送给模型的用户消息模板。
- 提示词装配、历史消息和 Provider payload 数据流。

排除：

- 普通按钮名称、placeholder、设置说明等不会进入模型的 UI 文案。
- 单元测试 fixture 和项目 README 等普通文档。
- 工具参数名称本身；仅在其描述会影响模型决策时纳入审计。

## 翻译约定

- 译文以“忠实表达当前英文原意”为原则，不在译文中偷偷修正原提示的错误。
- 工具名、字段名、角色名、扩展名和 JSON 示例保持原样。
- 为控制篇幅，重复的 JSON/XML 示例保留原结构，只翻译周围的解释文字；这仍覆盖了模型收到的全部语义指令。
- 每节附源路径和行号范围，以便直接回查。

## 一句话结论

当前问题主要不是“提示词不够强”，而是**提示词层级过多、职责重复、注册信息漂移、历史上下文无窗口管理**。模型同时要记住文件格式路由、工具分层、委派、Todo、输出格式、动态开关和大量失败处理，容易把注意力花在流程合规上，而不是用户任务本身。
